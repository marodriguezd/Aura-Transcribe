# Changelog

Change log of **Aura Transcribe** (Next-Gen evolution of [notune/android_transcribe_app](https://github.com/notune/android_transcribe_app)).

# Unreleased — Android 17 (API 37) platform pass

Platform, build and documentation hardening; no new user-facing features, and the version stays `0.2.2`.

- **Android 17 / API 37:** `compileSdk` and `targetSdk` raised from 35 to **37**. The project previously described itself as "Android 17 Ready (API 35+)", which was wrong on both counts — API 35 is Android 15. `minSdk` remains 26 (Android 8.0).
- **Toolchain:** Android Gradle Plugin 8.7.3 → **9.4.1**, Gradle wrapper 8.9 → **9.8.0**, Android NDK `28.0.13004108` → **`28.2.13676358`** (Gradle, the CI workflows and the docs now name the same version).
- **Release optimisation:** R8 minification and resource shrinking are now **enabled** for release builds (both were previously `false`), with narrowly scoped keep rules in `app/proguard-rules.pro` covering the JNI entry points, the Java callbacks Rust invokes by name, and the reflective ML Kit/Tink surfaces.
- **Performance measurement:** new `:benchmark` module providing Macrobenchmark startup tests and Baseline Profile generation. It requires a connected arm64 device and is deliberately excluded from CI; the existing in-app native ASR benchmark is unchanged and still covers inference throughput.
- **Build portability:** the hard-coded `android.aapt2FromMavenOverride` Termux path was removed from `gradle.properties` (commented out, with instructions), because pointing it at a non-existent file breaks every resource task on non-Termux hosts.
- **Naming:** root project renamed `OfflineVoiceInput` → `AuraTranscribe`.
- **Corrected capability claim:** the NPU (NNAPI) and GPU (Vulkan) hardware-backend options were never implemented in the native engine and must not be presented as working capabilities.
- **Documentation corrections:** in `README.md`, `ABOUT.md` and this file — the stale "Android 17 Ready (API 35+)" claim, an incorrect `PROJECT_MEDIA` adb command that used the old `dev.notune.transcribe` runtime package (the runtime package is `com.auratranscribe.app`), an inaccurate "isolated `:ime` process" architecture description (the manifest declares no `android:process`), an unsupported MediaProjection workaround presented as a normal feature, and privacy wording that implied nothing is ever transmitted.
- **Bounded-memory audio-file transcription:** `TranscribeFileActivity` no longer decodes a file into memory as a whole. It decodes and transcribes one 30-second chunk at a time and releases each chunk before decoding the next, so peak heap is independent of file length. Previously the decoded audio existed as three simultaneous full copies (a `List<float[]>`, a merged `float[]`, and a resampled `float[]`) before the native side copied it a fourth time; on a 30-minute recording that is roughly 350 MB of live float data. The 30-minute limit is kept, but is now a policy cap on processing time rather than the thing standing between the app and an OOM. Cancellation, operation ids, late-callback rejection and optional post-processing are unchanged, and the decoder's own output format is now honoured when it disagrees with the container header.
- **Native alignment gate actually runs:** a local function declared inside a `tasks.register { }` lambda meant `checkNativeAlignment` was never registered at all, so `check` silently did not depend on it. It is now registered, and it verifies the 16 KB page alignment of AGP's freshly merged native libraries for every built variant (which is how the 4 KB-aligned `libtranslate_jni.so` in mlkit-translate 17.0.2 was caught, and why the dependency is on 17.0.3).
- **Release builds no longer require the project's keystore to compile.** `app/build.gradle.kts` attached `signingConfigs.release` to the release build type even when `release.keystore` was absent, which made AGP abort `validateSigningRelease` with *"Keystore file not set for signing config release"*. The signing config is now attached only when a keystore actually backs it, so a fresh clone — and, importantly, F-Droid's buildserver, which compiles from source and signs the APK itself — gets an `app-release-unsigned.apk` instead of a failed build. The hardening is unchanged where it matters: if the keystore *is* present and `STORE_PASS`/`KEY_ALIAS`/`KEY_PASS` are missing on a release-targeting task, the build still fails fast rather than signing with default credentials.
- **Fastlane / F-Droid metadata:** the `fdroid_export` lane emitted `License: Apache-2.0` and pointed its source, issue-tracker and changelog URLs at an unrelated upstream repository; it now emits MIT and this repository's own URLs, with the pinned NDK version instead of a loose `r28`.
- **Adaptive large-screen layout:** the settings, models, custom-words, live-subtitle and accessibility-disclosure screens inset their content with `@dimen/content_horizontal_margin`, which is 16dp on compact windows and re-declared as 48dp in `values-w600dp/` and 140dp in `values-w840dp/`. Previously that dimen existed but was referenced by a single screen, so the main screens still stretched full-bleed on a tablet. The per-screen 16dp horizontal padding was folded into the margin so a phone renders exactly as before.
- **Lint debt:** `lintDebug` is back to zero errors and almost all the way down on warnings (205 → **18**, in two passes), by fixing the underlying issues rather than suppressing them. The remaining warnings are each deliberate and documented at the site they point to (five `InflateParams` false positives for views owned by `WindowManager` or returned from `onCreateInputView()`; three `UselessParent` and one `MergeRootFrame` where the extra container *is* the tap target, the scrim gutter, or the insets target; one `ObsoleteSdkInt` for `mipmap-anydpi-v26`, whose `-v26` qualifier AAPT2 requires; two `ButtonOrder` for an IME/overlay tool strip rather than a dialog; two `ApplySharedPref` for ordered synchronous commits the marker-file migration depends on; one `UnusedAttribute` for `enableOnBackInvokedCallback` and one for `isAccessibilityTool`, both of which are meaningful on the API levels that read them; one `ChromeOsAbiSupport`, because the app is arm64-only by design; and one `TooManyViews` on the settings screen). The three errors were genuine: a `BluetoothAdapter` state constant compared against the wrong constant set, a `GET_DEVICES_ALL` flag the API does not document (now the explicit `GET_DEVICES_INPUTS | GET_DEVICES_OUTPUTS` union), and a French string whose literal `100%` was parsed as a `% h` format specifier. The dead API-level guards behind `ObsoleteSdkInt` were removed as well: with `minSdk 26`, every `SDK_INT >= M/N/O` branch (and the `P` checks inside `@TargetApi(31)` methods) is unreachable, so the legacy `AudioRecord`/audio-focus/`TYPE_PHONE` fallbacks were deleted rather than left as untestable code.
- **Foreground-service type honesty on API 29:** `FloatingOverlayService` promoted itself with `FOREGROUND_SERVICE_TYPE_MICROPHONE` from API 29, but that constant — and the microphone FGS type itself — only exists from API 30. On Android 10 the type bit did not match the manifest's declared mask, which can throw `IllegalArgumentException` from `startForeground()`. The typed call is now gated at API 30 and Android 10 uses the two-argument form. This is also why `RustInputMethodService.switchToPreviousInputMethodSafe()` no longer carries `@TargetApi(P)`: that annotation told lint the body only runs on API 28+, which would have flagged the genuinely necessary guard as dead code.
- **MediaProjection foreground-service ordering corrected (second pass).** The earlier pass had it backwards: it started the foreground service first and only then obtained the projection, on the belief that the platform required that order. The documented contract for the `mediaProjection` FGS type is consent (`createScreenCaptureIntent()`) → `startForeground(…, FOREGROUND_SERVICE_TYPE_MEDIA_PROJECTION)` → `getMediaProjection()`. `LiveSubtitleService` now follows it, and calls `getMediaProjection()` only after the service is in the foreground; the failure path stops the foreground service explicitly instead of orphaning its notification.
- **Untrusted-Intent hardening in the file-transcription entry point.** `TranscribeFileActivity` is exported for `SEND`/`VIEW` of `audio/*`, so any app can hand it an Intent. `EXTRA_STREAM` is now read with `IntentCompat.getParcelableExtra(intent, EXTRA_STREAM, Uri.class)`; the deprecated `getParcelableExtra(String)` performed an unchecked cast at the call site, so a caller that put a non-`Uri` Parcelable there crashed the receiver with `ClassCastException`.
- **Two silent dead ends in file transcription now report themselves.** A file with no audio track used to `return` quietly, leaving the screen on "Transcribing…" with a progress bar forever; a file that decoded fine but contained no speech reported "Could not decode audio file". Each now shows the error that matches what happened, and the previously unreachable `file_error_decode` string was removed from all seven locales.
- **Duration cap moved into a pure, unit-tested helper.** `FileAudioChunks.exceedsDurationCap(frames, rate, seconds)` replaced an inline integer division that floored a file slightly over the 30-minute cap back to exactly the cap, so it was accepted. Eleven new tests join `FileAudioChunksTest`, covering the resampler's upsampling path, non-integer ratios, the guarantee that it does not alias the reused chunk buffer, and the cap at several sample rates. The JVM suite grew to 159 tests with that change (176 in the current tree).
- **`android:supportsRtl="true"`.** The layouts were already start/end-clean and no Java code hard-codes `Gravity.LEFT`/`RIGHT`, so mirroring is correct; the declaration was the only thing missing. The floating bubble's absolute window coordinates are not mirrored by the platform, so its behaviour is unchanged.
- **`android:isAccessibilityTool="false"` declared explicitly** in `accessibility_service_config.xml`. The platform default is already `false` (verified against `AccessibilityServiceInfo`), so behaviour is identical, but the attribute decides whether Play's prominent-disclosure requirement applies and this service is not an accessibility tool. `AccessibilityDisclosureActivity` is the disclosure that requirement asks for.
- **On-device (S1-mini) post-processing is now unreachable, not just documented as a placeholder.** `src/post_processor.rs::normalize_text_on_device` checks the downloaded model and builds the S1 prompt but performs no inference and returns trimmed input. A placeholder that users can still select is a feature that lies, so the provider is now gated behind `SettingsManager.LOCAL_S1_INFERENCE_AVAILABLE = false`: it reads *“unavailable in this build”*, its enable switch cannot be turned on, its download button is hidden, and a stale `pp_provider` marker that still names it gets `PostProcessor.LOCAL_S1_UNAVAILABLE_ERROR` instead of a fake “refined” result. The reason is a hard dependency gap rather than unfinished glue — the only inference backend in the dependency graph is `transcribe-cpp 0.1.3`, whose public surface is speech recognition (`Task::Transcribe | Translate`); there is no text-generation entry point, sampler or tokenizer-encode path, and S1-mini is a Qwen-based causal LM that would need a llama.cpp-class engine. `pack_ultralight_desc` was rewritten in all seven locales to stop promising the refinement. Because the gate is a `static final false` compile-time constant, R8 folds the branch in the optimized build and the whole on-device path disappears from the release DEX: `nativeNormalizeOnDevice`, `nativeSetS1ModelPath`, `nativeUnloadS1` and `nativeIsS1Loaded` are all absent, together with their callers — verified by reading the release DEX string table, which is the strongest form of "this cannot be reached". `nativeTrimMemory` stays, because `App.onTrimMemory` really calls it.
- **Release-verification findings recorded.** The R8 keep rules were validated against the release DEX's own string table, and the signed APK passes `zipalign -c -P 16 4` and `apksigner verify`.
- **The APK/AAB model-packaging hazard is fixed at the root, not just documented.** `app/build.gradle.kts` used to decide whether to put the GGUF in the base module by sniffing the whole command line for `"bundle"`, so a single invocation that asked for both `assembleRelease` and `bundleRelease` silently produced a **32 MB APK with no model** and reported success; the same sniff made `downloadModels` skip a `assembleDebug assembleRelease` run. A combined APK+bundle invocation now fails during configuration with an actionable message naming both task sets, because the two artifacts genuinely need different asset layouts (the APK needs the GGUF in the base module; the AAB must keep it only in the `:model_assets` install-time asset pack, or it ships ~750 MB twice). `downloadModels` now keys off a release-producing task rather than off a `Debug` task being absent. Both artifacts are additionally gated on their *actual contents*: `verifyReleaseApkModel` (after `packageRelease`) and `verifyReleaseBundleModel` (after `signReleaseBundle`, which is what writes `outputs/bundle/release`) open the archive, match `assets/builtin-model/<name>` by suffix — which catches both a missing model and a duplicate-delivery layout — and compare the packaged entry size against the source asset. `checkModels` still verifies the source SHA-256; it can no longer stand in for delivery. The only way to produce a model-less release APK is to pass `-Pauratranscribe.allowModelLessReleaseApk=true`, and it prints that the result is not distributable. An AAB has no opt-out. All four cases were verified from the artifacts: APK alone (745,492,893 bytes with the model), AAB alone (728,364,695 bytes with the model only under `model_assets/`), the combined invocation (fails), and a missing source asset (both artifact gates fail; the opt-out succeeds and warns).
- **Startup no longer touches the disk on the main thread.** `MainActivity.maybeDownloadDebugModel()` ran `getAssets().list("builtin-model")` and read the `active_model` marker synchronously from `onCreate()`/`onResume()`, which debug StrictMode reported. The two probes now live in `ModelAvailability` — deliberately free of `Context`, views and dialogs so a worker can call them — and run on a `"model-probe"` thread; the boolean is handed back through `runOnUiThread` with an `isFinishing()/isDestroyed()` check, a generation counter that drops a superseded result, and an in-flight flag that keeps the cold-start `onCreate`+`onResume` pair from probing twice. While the probe runs, the status line shows the `status_checking` string that was already the layout default, and the native engine overwrites it with `Ready`. Detection behaviour itself is unchanged (it still uses `exists()`, not `isFile()`), and new JVM tests in `ModelAvailabilityTest` cover an empty marker, a marker naming a missing file, whitespace trimming, a same-named file in the wrong directory, a marker pointing into a missing `models/` directory and a model in a subdirectory of `models/` — the suite is now **176 tests**.
- **The test gate could not actually fail, and now it can.** `debug_telegram.yml` ran `./gradlew testDebugUnitTest 2>&1 | tee gradle_test.log` without `pipefail`, so the step's exit status was `tee`'s — always `0`. A red unit-test run reported a green "hard gate". Every piped gate in both workflows now sets `set -e -o pipefail`.
- **Pull requests now run the same gates as a push.** `debug_telegram.yml` gained a `pull_request:` trigger, so a PR cannot land with failing tests, lint, alignment or packaging checks. The distribution steps are guarded with `github.event_name != 'pull_request'`: a PR gets the gates and the workflow artifact, never a Telegram message (the secrets do not exist on fork builds).
- **CI now runs the gates the project actually has.** The debug workflow previously stopped at tests, lint and `checkModels`. It now also runs `:app:checkNativeAlignment` (16 KB page alignment of every shipped `.so` — before this, a misaligned dependency could only fail a local build), `:app:verifyPackagingDecision`, `:benchmark:assembleBenchmark`, `python3 scripts/test_verify_release_artifact.py` and `python3 scripts/bench_performance.py`, and dumps every gate's log when something fails.
- **Release signability is now explicit and fail-safe.** The release workflow gained a credential preflight that asserts `KEYSTORE_BASE64`, `STORE_PASS`, `KEY_ALIAS` and `KEY_PASS` are all present and exits `1` before the expensive build if any is missing — checking presence only, never echoing a value. It explicitly rejects a `*-unsigned.apk` by name, and it refuses to publish an artifact whose signer certificate SHA-256 equals `keystore/debug.keystore`'s `androiddebugkey` (for the AAB, the equivalent check via `keytool -printcert -jarfile`). An unsigned build is still reachable by anyone compiling from source — that is the F-Droid-style path and it stays — but a CI release can no longer be an unsigned artifact wearing a signed release's name.
- **The release pipeline verifies the AAB it now builds, and checks the right alignment.** `android_release.yml` verifies the APK with `zipalign -c -P 16 -v 4` (the previous `-c 4` only ever proved 4-byte alignment, not Android 17's 16 KB requirement) and builds the app bundle in a **separate** `bundleRelease` invocation, verifying it as a JAR rather than an APK: `jarsigner -verify -certs` output is inspected for `jar is unsigned` (the command exits `0` even for an unsigned bundle) before `keytool -printcert -jarfile`. Both artifacts are uploaded and published only after every gate passes. Both workflows also fail if the model-less release escape hatch appears in a workflow file or in an `ORG_GRADLE_PROJECT_*` variable — the needle is assembled from two halves so the guard does not match its own source line.
- **The APK/AAB packaging decision is now a tested contract, not a heuristic on the command line.** The decision moved into pure functions (`packagingTaskSets`, `packagingDecision`, classifying an invocation as `apk`/`bundle`/`ambiguous`/`neither`), and a new `:app:verifyPackagingDecision` task — a hard gate in both workflows and a dependency of `check` — drives them, together with the real model gates, over 17 representative invocations and 9 synthetic archives (`apk-ok`, `aab-ok`, duplicated, wrong directory, truncated, no-model, multi-entry). It asserts both directions (a valid archive must pass, an invalid one must be rejected), so a regression in either the decision or the verifier fails the build instead of being reproduced by a test that recomputes the expected answer on its own. Non-vacuity was proved twice by perturbing the production code and watching the gate fail.
- **Independent release-artifact verification.** New `scripts/verify_release_artifact.py` verifies an already-built `--kind apk|aab` artifact by content: the GGUF must appear exactly once, under `assets/builtin-model/<name>` (rejecting a copy outside the asset pack in an AAB), with the same size and SHA-256 as the verified source asset. It refuses to pass when the source model directory is empty, and treats an unreadable zip as a failure. `scripts/test_verify_release_artifact.py` covers it with 14 stdlib-unittest cases and runs as a gate in both workflows (pure Python, no SDK or model download). Checked against the real debug APK, it fails as expected because that APK deliberately ships without the model.
- **`scripts/bench_performance.py` no longer reports a fabricated speed-up.** Its "streaming latency" figures were hardcoded constants (300 ms vs 80 ms, printed as "3.75x"), and it always printed `ALL OPTIMIZATIONS VERIFIED (PASS)` and exited `0`, so the CI step named "optimization gate" gated nothing. It now states in its header that it times pure-Python stand-ins rather than device data, **differentially asserts** every fast path against its naive reference (RMS of a ±0.5 square wave is exactly 0.5 and silence is 0; the sliding block-sum matches the naive scan and finds the planted silent region; precomputed bigram norms yield identical cosine values; the banded Levenshtein equals the full matrix and rejects pairs more than two edits apart), and exits `1` on any mismatch. That differential check immediately caught a real bug in the stand-in: the banded DP reused rows without resetting out-of-band cells to infinity, so `telefono`/`microfono` — genuinely 5 edits apart — was reported as 2. Timings are now diagnostics only, and the CI step is named "Reference-algorithm micro-benchmarks (correctness gate)".
- **The unavailable S1-mini provider cannot be re-enabled by a stale save path.** The settings screen's save logic now funnels through a single rule, `SettingsManager.resolveEnabledOnSave(providerId, requested)`, which returns `requested && isProviderAvailable(providerId)`. Two tests pin the contract: an unavailable provider cannot be persisted as enabled, and the provider catalogue has to stay consistent with the availability flag (the local entry is still listed, its label reads as unavailable while the flag is `false`, and every other provider is available with a non-empty label). `ModelAvailabilityTest` gained two more edge cases (a marker that points into a missing `models/` directory is not a model; a marker may name a model in a subdirectory of `models/`). The JVM suite is now **176 tests**.
- **Every remaining lint warning re-triaged against the current code.** A fresh `lintDebug` on the final tree reproduces exactly the same 18 warnings and 0 errors, and each was re-read in the code rather than trusted from the previous report. No genuine defect was found among them (details in `AGENTS.md` §3), and none is suppressed: the three sites whose justification was missing in-file (the disclosure layout's “redundant” parent, and the two `ButtonOrder` warnings on the IME/overlay tool strips) now carry it next to the element they point at. Two `UnusedAttribute` warnings and `TooManyViews` cannot carry an inline note — an attribute inside the `<application>` tag has nowhere to put a comment, and a view count is a property of the whole layout — so their reasons are recorded in `AGENTS.md` and here instead.

# v0.2.2

Major audio & hardware release introducing native `AudioRecordBridge` communication pipeline, zero-latency Bluetooth pre-warming handshake, dynamic headset visual indicators, real-time microphone diagnostics, poison-tolerant concurrency hardening, and 100% i18n parity:

- **Dedicated Native `AudioRecordBridge` Communication Pipeline:** Implemented high-performance Java `AudioRecord` bridge operating in `VOICE_COMMUNICATION` mode (16 kHz 16-bit mono PCM) with direct `ByteBuffer` allocation and native JNI streaming (`pushAudioDirect`), forcing active microphone capture on wireless Bluetooth earbuds (AirPods, Galaxy Buds, Pixel Buds, Sony, etc.) and headset SCO/BLE devices.
- **Zero-Latency Bluetooth Pre-Warming Handshake:** Pre-warms the Bluetooth communication pipe in the background when the on-screen keyboard (`RustInputMethodService`) or floating overlay bubble (`FloatingOverlayService`) opens, eliminating the 300–500 ms connection handshake lag.
- **Dynamic Headset / Mic Indicators:** Visual real-time indicator on both the keyboard record button and floating dictation bubble, dynamically rendering 🎧 (`ic_headset`) for Bluetooth input and 🎙️ (`ic_mic`) for internal microphone.
- **Microphone Diagnostics & Live Sound Test:** Comprehensive sound test UI in `MainActivity` with real-time RMS decibel level meter (`MicLevelView`), active device indicator, and 1-tap start/stop verification.
- **Multi-Agent Robustness & Concurrency Hardening (Victory Audit):** Bounded `ByteBuffer` reuse, poison-tolerant mutex guards in Rust, atomic session generation validation, idempotent `cleanupNative` teardowns, and comprehensive `AudioRecordBridgeTest.java` suite (the JVM test suite currently contains 123 `@Test` methods across 18 classes).
- **100% i18n Parity (266 Strings across 6 Locales):** Complete translation coverage across German, Spanish, French, Italian, Portuguese, and Russian.

- **100% i18n Parity (257 Strings across 6 Locales):** Complete translation coverage in all supported locales (`de`, `es`, `fr`, `it`, `pt`, `ru`).
- **Guardrail & Audio Test Suite:** Added plain-JVM decoupled unit test suite `PostProcessConfigurationGuardTest.java` and audio device routing suite `AudioDeviceManagerTest.java`.
