# 🛠️ Unreleased — Android 17 (API 37) Platform & Quality Pass

> **Not yet tagged.** These notes describe work that is in the tree but has **not** been released: the version is still **0.2.2 (`versionCode 41`)** and no new version number or release date has been assigned. The CI workflow uses this whole file as the GitHub release body, so this block is what will ship once a `vX.Y.Z` tag is cut.

### 🎯 Platform: Android 17 / API 37

- **`compileSdk` / `targetSdk` raised to 37.** The project previously described itself as "Android 17 Ready (API 35+)" — wrong on both counts, since **API 35 is Android 15** and **API 37 is Android 17**. `minSdk` stays 26 (Android 8.0).
- **Toolchain moved to the API 37 line:** Android Gradle Plugin **9.4.1**, Gradle wrapper **9.8.0**, Android NDK **28.2.13676358**. AGP 8.13.x physically cannot resolve the API 37 platform (it is tested up to compile SDK 36.1 and looks for `android-37` while the SDK installer creates `android-37.0`), which is why the major AGP jump is required rather than cosmetic.

### 🚀 Release build

- **R8 minification and resource shrinking are now enabled for release** (`isMinifyEnabled = true`, `isShrinkResources = true`). Previously the release build shipped completely unminified. Keep rules are narrowly scoped in `app/proguard-rules.pro` and cover only what genuinely needs preserving: the JNI entry points, the Java callbacks Rust invokes by name, framework components referenced from resource XML, and the reflective surface of ML Kit / Tink / OkHttp.
- A **`benchmark` build type** and a new **`:benchmark` module** (Macrobenchmark + Baseline Profile generation) were added. It is deliberately excluded from CI, since it needs a connected arm64 device.
- **Building an APK and an app bundle in one invocation now fails instead of shipping a model-less APK.** The APK carries the built-in speech model in the base module; the AAB must carry it only in the `:model_assets` install-time asset pack. The build script used to decide which of the two layouts to use by looking for `bundle` anywhere in the command line, so `./gradlew assembleRelease bundleRelease` produced a 32 MB APK with **no model inside** and still reported success — and the same guess could skip the model download for `assembleDebug assembleRelease`. The two artifact layouts are now chosen per artifact, the ambiguous invocation stops at configuration time with a message naming the tasks involved, and both release artifacts are verified by opening them: the model must be present, exactly once, with the same size as the source asset. The only way to produce a model-less release APK is to ask for one explicitly with `-Pauratranscribe.allowModelLessReleaseApk=true`, which prints that the artifact is not distributable. Build the two artifacts in separate invocations, as the CI workflows already do.

### 🎨 Material 3 & visual coherence

- **The theme is now driven entirely by Material 3 theme attributes.** The hard-coded blue/white palette is gone, the white record drawable no longer stays pure white in dark mode, and Dynamic Color is no longer undermined by custom drawables. Light and dark are coherent by construction because the app uses the Material tonal scheme as designed instead of overriding only `colorPrimary`/`colorOnPrimary`.
- **Adaptive content width on large screens.** The settings, models, custom-words, live-subtitle and disclosure screens now inset their content by a margin that follows the window size class — 16dp on a phone, 48dp on a tablet or phone-landscape window, 140dp on a tablet in landscape or an unfolded foldable. Chrome (the app bar) stays full-bleed; only the reading column narrows, so lines of text stop stretching edge to edge on a 12" screen. The single source of that inset is `@dimen/content_horizontal_margin`, overridden in `values-w600dp/` and `values-w840dp/`.
- **48dp minimum touch targets** across the IME key row, the voice popup's close button, the floating overlay's controls and the live-subtitle close button. Glyphs stay small; the interactive container meets the accessibility minimum.
- The IME record area was shrunk from an Activity-sized 200dp block to a keyboard-sized surface, and long streaming partials are no longer clipped.

### ♿ Accessibility

- **New prominent in-app disclosure screen for the optional Accessibility service**, localized in all seven supported locales. It explains what the service can read (only the focused text field), why it is optional (without it, dictation is copied to the clipboard instead), and how to revoke it. The user is only sent to Android's settings after explicitly continuing, and the app never enables the service on their behalf.
- The accessibility service configuration was narrowed to what the feature actually needs: only focus and window-state events, no interactive-window enumeration, and a real label/description instead of repeating the app name.
- **Dictation insertion now respects the cursor and the selection.** The fallback path used to build `existing + " " + text`, which appended to the end of the field when the cursor was mid-sentence and destroyed the field's content order when text was selected. It now inserts at the real selection and restores the caret after the inserted text, with unit tests covering the unknown/invalid-selection cases.
- **`READ_USER_DICTIONARY` removed.** The platform keeps this permission out of the public SDK, so an app targeting a modern SDK can never be granted it; declaring it advertised access the app could not hold while the dictionary query silently failed on every launch. Android's Personal Dictionary is still reachable from the UI.

### 🐛 Fixes

- **Live subtitles on Android 14+, correctly this time.** An earlier pass reversed this ordering on the belief that the foreground service had to start *before* `getMediaProjection()` could succeed — the opposite of what the platform documents. The documented contract for the `mediaProjection` type is: (1) the Activity calls `createScreenCaptureIntent()` and the user consents, (2) the service calls `startForeground()` with the `mediaProjection` type, (3) only then may `MediaProjectionManager.getMediaProjection()` be called. Calling it earlier throws `SecurityException("Media projections require a foreground service of type ServiceInfo.FOREGROUND_SERVICE_TYPE_MEDIA_PROJECTION")`, which was caught and turned into a silent `stopSelf()`, so live subtitles never started. `LiveSubtitleService` now follows the documented order; the failure path also tears the foreground service down explicitly instead of leaving its notification behind.
- **NPU/GPU options removed from the models screen.** The engine reads the `hardware_backend` marker and only logs it — there is no NNAPI or Vulkan code path — so offering "NPU" and "GPU" told users the opposite of what was happening. The screen now states the one backend that exists (CPU, ARM NEON + dotprod + fp16) and normalises any stale value.
- Audio focus now requests a cooperative `AUDIOFOCUS_GAIN_TRANSIENT` instead of the exclusive transient gain, so dictation pauses other audio rather than demanding the whole audio device.
- Debug-only StrictMode diagnostics for main-thread disk/network I/O and leaked resources.
- **Audio-file transcription no longer holds the whole file in memory.** It decodes and transcribes one 30-second chunk at a time and releases each chunk before decoding the next, so peak memory is the same for a ten-second clip and a half-hour recording. Previously three full copies of the decoded audio were alive at once (and the native side made a fourth) — about 350 MB for a 30-minute file. The 30-minute limit now exists to bound processing time, not to prevent the app from running out of memory.
- **`MainActivity` no longer leaks itself.** The static reference used to notify "whichever instance is on screen" during a model download was a strong reference, which pinned the Activity and its entire view tree for the life of the process; it is now a `WeakReference`.
- **Startup no longer reads the disk on the main thread.** Creating or resuming the main screen enumerated the bundled assets (`getAssets().list`) and read the `active_model` marker synchronously, which debug StrictMode reported as main-thread disk I/O. Both checks now run on a background thread and post their answer back to the UI, guarded so a late result cannot overwrite newer state and so the cold-start `onCreate`/`onResume` pair probes only once. Model detection itself is unchanged, and the status line shows the existing "Checking assets…" state while the check runs.
- **Accessibility click events on custom controls.** The dictation bubble, the subtitle overlay and the IME's space/backspace keys handle `onTouch` directly, which bypassed the framework's click dispatch; they now report the click so accessibility services receive it.
- **Free-space checks account for reclaimable cache.** The model-download and model-import pre-flight checks used `getUsableSpace()`, which ignores the cache Android is allowed to clear for the app, so a nearly-full device could refuse a download that would in fact have fit.
- **Release builds no longer need the project's keystore to compile.** When `release.keystore` was absent, the release build type was still given a signing config with no `storeFile`, so AGP failed the build outright (`Keystore file not set for signing config release`) instead of producing an unsigned APK. A fresh clone, and F-Droid's buildserver (which builds from source and signs the APK itself), could not build a release at all. The signing config is now attached only when a keystore exists; the safety rule is untouched — a present keystore with missing credentials on a release task still refuses to sign rather than falling back to default passwords.
- **Foreground-service type on Android 10.** The floating dictation bubble started its foreground service with the `microphone` type unconditionally, but that type — and the matching `FOREGROUND_SERVICE_TYPE_MICROPHONE` constant — only exists from Android 11. On Android 10 the type bit did not match what the manifest declares, which the platform can reject by throwing from `startForeground()` (the exception was caught and turned into a silent stop, so the bubble just never appeared). Android 10 now uses the two-argument form; Android 11+ keeps the typed call.
- **F-Droid metadata corrected.** The export lane declared an Apache-2.0 licence and pointed at an unrelated upstream repository; it now emits the project's real MIT licence and its own source, issue-tracker and changelog URLs.
- **Dead API-level guards removed.** With `minSdk 26`, every `SDK_INT >= M/N/O` check and every `P` check inside an API-31-only helper was unreachable. The legacy `AudioRecord`, audio-focus, `TYPE_PHONE` overlay and pre-`NotificationChannel` fallbacks they protected were deleted after a `lintDebug` pass confirmed the findings, leaving no untestable code paths behind.
- **Lint re-triaged on the final tree: 0 errors, 18 warnings, none suppressed.** The warning count did not just carry over — every remaining warning was re-read against the code it points at. No genuine defect was found in the set (five false-positive `InflateParams` for views owned by `WindowManager` or returned from `onCreateInputView()`; the container that lint calls redundant in three layouts and one merge candidate *is* the full-screen tap target, the scrim gutter, or the view the insets listener applies padding to; `mipmap-anydpi-v26` needs its `-v26` qualifier for AAPT2; the two `ButtonOrder` hits are IME/overlay tool strips, not dialog button pairs; the two `ApplySharedPref` hits are the ordered synchronous commits the settings migration depends on and they run on a background thread; the two `UnusedAttribute` entries are meaningful on the API levels that read them; the app is arm64-only by design; and `TooManyViews` is the settings screen). Nothing is silenced with `tools:ignore` or `@SuppressLint`, and each reason now sits next to the element it concerns.
- **A shared audio file can no longer take the app down or leave it spinning.** Transcribe-file is an exported target for `audio/*`, so its Intent is untrusted input: `EXTRA_STREAM` is now read with the type-checked `IntentCompat.getParcelableExtra(…, Uri.class)`, where the deprecated overload performed an unchecked cast and let any caller crash the receiver by sending a non-`Uri` Parcelable. Two silent dead ends are also fixed: a file with **no audio track** used to return quietly, leaving the screen on "Transcribing…" with a progress bar forever (the caller only reacts to an exception or a delivered transcript); and a file that decoded successfully but contained **no speech** reported "Could not decode audio file", sending users after a format problem that did not exist. Each case now reports what actually happened.
- **The 30-minute duration cap is unit-tested.** The check moved out of the decode loop into `FileAudioChunks.exceedsDurationCap(frames, rate, seconds)` and is compared in floating point: the previous integer division floored a file that was a fraction of a second over the cap back to exactly the cap, so it was accepted. Eleven new JVM tests cover the resampler's upsampling path, its non-integer ratios (44.1/48/32 kHz → 16 kHz), its guarantee that it never aliases the reused chunk buffer, and the cap across sample rates.

### 🔒 Hardening & honesty

- **The Accessibility service declares that it is not an accessibility tool.** `android:isAccessibilityTool="false"` is now written out explicitly in `accessibility_service_config.xml`. Platform behaviour is unchanged — `AccessibilityServiceInfo` parses the attribute with a default of `false` — but the declaration is what Google Play reads when deciding whether the prominent-disclosure requirement applies, and this app is a dictation convenience, not a tool whose primary purpose is disability support. The in-context disclosure screen it depends on was already in place.
- **RTL support is enabled.** Every layout was already written with `start`/`end` attributes and there is no hard-coded `Gravity.LEFT`/`RIGHT` anywhere in the Java sources, so mirroring is correct; `android:supportsRtl="true"` was the missing declaration. The floating bubble is positioned in absolute window coordinates, which the platform does not mirror, so its drag-and-snap behaviour is unaffected.
- **On-device (S1-mini) post-processing can no longer masquerade as a working feature.** `src/post_processor.rs::normalize_text_on_device` validates the downloaded model file, builds the real S1 prompt and then discards it: it performs no inference and returns the trimmed input. Every layer around it is real (download, path resolution, prompt construction, idle unload, `onTrimMemory` hook), but the inference itself cannot be completed with what the project ships — the only backend in the dependency graph is `transcribe-cpp 0.1.3`, whose public API is speech recognition (`Task::Transcribe | Translate`), with no prompt-decode, sampler or tokenizer-encode entry point; S1-mini is a Qwen-based causal LM that would need a llama.cpp-class engine. Rather than leave a placeholder users can select, the provider is now gated off: it is labelled *unavailable in this build*, its switch cannot be enabled, its download button is hidden, and a stale saved provider gets an explicit error instead of a fake "refined" transcript. The pack description was rewritten in all seven locales so it no longer promises the feature, and the store-facing copy does not claim it either.
- **Verified release artefacts.** Release builds were checked end to end: R8 keeps every live JNI symbol (confirmed by reading the names out of the release DEX's string table rather than trusting the keep rules), the signed APK passes `zipalign -c -P 16 4` and `apksigner verify`, it carries only `arm64-v8a` native code, a standalone `assembleRelease` does contain the bundled model, and `bundleRelease` delivers it through the `:model_assets` asset pack — exactly once, as both artifacts are now verified by opening them.  The former trap — asking for an APK and a bundle in the *same* Gradle invocation produced a model-less 32 MB APK while reporting success — is no longer possible: that invocation now fails during configuration with a message naming the conflicting tasks.

### 🛡️ Release integrity and CI

These are process guarantees rather than features: they exist so the fixes above cannot silently come back.

- **The unit-test gate could not fail, and now it can.** CI ran the tests as `./gradlew testDebugUnitTest 2>&1 | tee gradle_test.log` without `pipefail`, so every step's exit status was `tee`'s — always success. A failing test run reported a green hard gate. Both workflows now set `set -e -o pipefail` on every piped gate, and pull requests run those gates too (a PR never gets a Telegram notification; the distribution steps are guarded).
- **A release can no longer be an unsigned artifact presented as a signed one.** The release workflow checks all four signing secrets before the expensive build and fails if any is missing, never printing their values; it refuses to publish an `app-release-unsigned.apk`; and it rejects an artifact whose signer certificate is the repository's own debug key, for the APK (`apksigner`) and the AAB (`keytool -printcert -jarfile`) alike. Compiling from source without a keystore still produces an unsigned APK on purpose — that is the path an F-Droid-style buildserver needs — but it is not a release channel here.
- **Alignment and bundle signatures are now verified properly.** The APK check asks for `zipalign -c -P 16 -v 4`, the 16 KB requirement of Android 17, instead of the 4-byte check that can never catch a 4 KB-aligned library. The app bundle is verified as a JAR with `jarsigner -verify -certs`, and because that command exits `0` even for an unsigned bundle its *output* is inspected for `jar is unsigned`.
- **The model-delivery rules are enforced twice, in two independent ways.** The build itself opens the packaged APK and AAB (`verifyReleaseApkModel`, `verifyReleaseBundleModel`) and requires the GGUF exactly once; `scripts/verify_release_artifact.py` then re-checks the built artifact against the source asset by size and SHA-256 (rejecting a missing, duplicated, misplaced, truncated or corrupted model). A new `:app:verifyPackagingDecision` task drives the real packaging-decision functions and the real model gates over 17 representative invocations and 9 synthetic archives, asserting both that valid layouts pass and that invalid ones are rejected — so a regression fails the build rather than being re-derived by the test.
- **The performance script stopped inventing numbers.** `scripts/bench_performance.py` had hardcoded "300 ms vs 80 ms" timings printed as a 3.75× speed-up, and always exited `0`. It now times pure-Python stand-ins, **asserts** that every fast path agrees with its naive reference, and exits `1` on any mismatch. That assertion found a real bug in the stand-in itself (a banded edit distance reused rows without resetting out-of-band cells, so a 5-edit pair was reported as 2). It is a correctness gate, not an on-device benchmark, and it is named accordingly.
- **The unavailable S1-mini provider is guarded at the save path too.** `SettingsManager.resolveEnabledOnSave()` is now the single rule deciding whether a provider may be persisted as enabled, so a stale preference or a programmatic save cannot turn the placeholder back on. Tests pin both that rule and the provider catalogue's consistency with the availability flag.
- **Nothing here is a claim about performance or hardware.** No device or emulator was available while making these changes, so instrumentation tests, Macrobenchmark measurements and Baseline Profile generation have still never been run — the `:benchmark` module compiling is not a measurement. Production signing was likewise not exercised end to end: what was verified is the failure behavior without credentials, plus the debug-key rejection (proved by showing that the debug keystore's SHA-256 equals the signer certificate of the debug APK).

# ✨ Aura Transcribe v0.2.2 — Bluetooth AudioRecord Bridge, Zero-Latency Pre-Warming & Diagnostics

`versionCode 41` — Major Audio & Hardware Release: Native `AudioRecordBridge` communication pipeline, zero-latency Bluetooth pre-warming handshake, dynamic headset visual indicators, real-time microphone diagnostics & sound test meter, poison-tolerant concurrency hardening, and 100% i18n parity.

### 🌟 Key Changes in v0.2.2

- **Dedicated Native `AudioRecordBridge` Communication Pipeline:** Direct high-performance Java `AudioRecord` bridge operating in `VOICE_COMMUNICATION` mode (16 kHz, 16-bit mono PCM). Leverages direct `ByteBuffer` allocation and native JNI streaming (`pushAudioDirect`) directly into the Rust ASR engine, forcing active microphone capture on wireless Bluetooth earbuds (AirPods, Galaxy Buds, Pixel Buds, Sony, etc.) and headset SCO/BLE devices.
- **Zero-Latency Bluetooth Pre-Warming Handshake:** Automatically pre-warms and establishes the audio communication pipe in the background the moment the on-screen keyboard (`RustInputMethodService`) or floating overlay bubble (`FloatingOverlayService`) appears on screen. Eliminates the initial 300–500 ms Bluetooth connection handshake latency when the user taps record.
- **Dynamic Device Indicators (🎧 / 🎙️):** Visual real-time indicator on both the keyboard record button and the floating dictation bubble. Dynamically switches to 🎧 (`ic_headset`) when Bluetooth headset input is active, and 🎙️ (`ic_mic`) when recording via the internal microphone.
- **Interactive Microphone Diagnostics & Real-Time Sound Test:** Added a comprehensive sound test section in `MainActivity` Settings. Features a live RMS decibel audio level meter (`MicLevelView`), active recording device label, and one-tap test start/stop to verify microphone levels and active routing before dictating.
- **Multi-Agent Robustness & Concurrency Hardening (Victory Audit):**
  - Eliminated memory leaks and ensured bounded direct `ByteBuffer` reuse.
  - Poison-tolerant mutex guards in Rust and atomic session generation validation to prevent race conditions during rapid start/stop cycles.
  - Safe, idempotent JNI pointer cleanup (`cleanupNative`) and lifecycle teardowns across all services and activities.
  - Comprehensive unit test suite `AudioRecordBridgeTest.java` (109/109 JVM tests passed).
- **100% i18n Parity (266 Strings across 6 Locales):** Complete translation coverage across English, German, Spanish, French, Italian, Portuguese, and Russian.
